# AI Adoption in Organizations: Cheatsheet

Figures are rules of thumb; re-measure in your context. "Position" = judgment, not fact.

## Order of Adoption (ch01)
Data rules -> train key users + template -> 2-3 skills per team -> shared knowledge layer -> customer-facing assistant -> measure and review.

## First Project Filter
| Question | Good first project |
|---|---|
| Impact / complexity | High / low (quick win) |
| Where | Internal, reversible |
| Shape | Fixed workflow, model at named points |
| People | Owner named, human at both ends |
| Data | No restricted data, or anonymised |

## Training (ch02)
Assess -> workshop (hands-on, own tasks) -> champions with time -> second assessment after a few weeks.
Habits: speak instead of type · be interviewed by the assistant · ask the source of every number.
Leave behind: filled template + 2-3 skills per person.

## Where May the Text Go? (ch03)
| Class | Public free chat | Business plan / API | Company hardware |
|---|---|---|---|
| Public info | yes | yes | yes |
| Internal | no | check terms | yes |
| Personal / client | no | only with terms, location and consent checked | preferred |
| Restricted (health, ID, detailed finance) | no | only with explicit consent and professional advice | preferred |
Anonymise with placeholders; keep the mapping inside.

## Knowledge Layers (ch03)
Context · data · skills · intelligence (transcripts) · automations. Retrieval with citation + queries for numbers + deterministic workflow with small model calls. Source = owner + date + status + precedence.

## Customer / Staff Assistant (ch04)
Template approved · consent · global intents (person, appointment) · status pipeline with takeover · validate against registry · draft approved by a person where the company commits · layered sources for high-stakes answers · confirm spoken dates and emails · text-test before voice.

## Reading a Case (ch05)
Before in numbers? Who measured? Period? Full cost? Who benefits? Does the arithmetic reconcile? -> ideas yes, forecasts no.

## Pilot Measurement (ch05)
One unit of work · baseline (median + spread) · fixed period · costs incl. review, upkeep, training · errors and rework · saved vs redeployed time · stop/scale rules in advance.

## Risks and Responses (ch06)
| Risk | Response |
|---|---|
| Confident wrong answer | Sources, tests, sample review, shorter paths |
| Conflicting documents | Owner, date, precedence; contradiction sweep |
| Injection / over-broad access | Deny by default, approvals bound to actions, no keys in prompts |
| Cost loop | Step limit, spend cap, no auto top-up, kill switch |
| Generated app flaws | Second reviewer, platform review, expert for high stakes |
| Unfiltered model | Own systems or written permission only; scoped; report -> fix -> retest |
| Regulation duties | Map use, train, keep record; verify text with a professional |

## Comparing Tools (ch07)
5-10 own tasks · written criteria · blind or second judge · cost per completed task · data terms, region, plan · portability · prototype vs production · review date.
