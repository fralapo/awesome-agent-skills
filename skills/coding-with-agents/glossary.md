# Glossary

**Agent** — a model run in a loop that reads files, runs tools and iterates with the human absent or only watching (ch06)
**Agentic QA** — a markdown plan telling an agent to act as a QA user, plus a second agent that confirms bugs (ch03)
**Announce-steps instruction** — telling the agent to state each significant step so you can steer (ch02)
**Attack surface** — the set of states reachable by an attacker under a stated security model (ch06)
**Backtest** — checking whether a model finds a known bug in the commit before its fix (ch01, ch03)
**Bandwidth-bound** — limited by memory throughput rather than compute (ch05, ch06)
**Baseline** — a measured starting point or benchmark the agent iterates against (ch02)
**Chain of thought** — reasoning text a model produces before the answer; a learned form of exploring internal states (ch06)
**Compaction** — summarising context to fit a window; a lossy step, a weak point of agents (ch06, ch07)
**Concept vs implementation** — deciding what and why versus writing the code (ch01)
**Context budget** — the fixed token cost of prefix, tool definitions and history that every step pays (ch07)
**Culture (of implementations)** — your earlier optimised projects used as examples for the agent (ch02)
**Design sacrifice** — consciously not building a complex feature (ch04)
**Desirable difficulty** — effort that builds understanding and should not be delegated away (ch05)
**Differential testing** — comparing the real implementation with a trivially correct one on random input (ch03)
**Eval** — a fixed set of cases with stated criteria, used to compare one change with another (ch08)
**Flow programming / vibe coding** — never reading the code, judging only effects (ch01, ch02)
**Greedy decoding** — temperature 0, always the highest-probability token (ch06)
**Harness** — the program around the model: tools, edit mechanism, context, state memory (ch02, ch06, ch07)
**Idempotency** — repeating an operation has the same effect as doing it once (ch06)
**Indirection** — a pointer or reference hop costing memory and time (ch04)
**Instructions file** — a file of stack preferences and constraints read by the agent (ch02)
**Invariant** — a property that must hold after every operation (ch03)
**Invisible AI** — AI that improves an existing feature without being shown as a chat (ch04)
**Irreversible decision** — language, framework, architecture, production schema, public API (ch04)
**Jevons effect** — cheaper tokens leading to more usage and higher total spend (ch06)
**Judge (LLM-as-judge)** — a model grading outputs against a rubric; valid only after calibration against labelled human cases (ch08)
**Kill switch** — an automatic stop for an agent exceeding its spending or action limits (ch06, ch07)
**Lethal combination** — private data, untrusted input and an outbound channel in one run; break at least one (ch07, ch08)
**Mixture of answers** — generating several answers then asking the model to write a new one from them (ch06)
**Observability** — interfaces that let the agent see real state (ch02)
**Pass@k and pass^k** — at least one of k attempts succeeds, versus all k succeed (ch08)
**Prefill** — the processing of the prompt before generation; batched for speed (ch06)
**Prompt caching** — reuse of computed state for an unchanged prompt prefix, making it cheaper (ch06)
**Result per token** — value obtained per unit of AI cost (ch06)
**Sampling** — choosing the next token among candidates; also shapes later state (ch06)
**Shadow mode** — the agent proposes, people act, and outcomes are compared before any autonomy is granted (ch08)
**Spec file** — written design and requirements that start an agent task (ch02)
**State coverage** — coverage of program states, as opposed to lines (ch03)
**Sub-agent** — a delegated run with its own window and tools, returning a conclusion rather than its transcript (ch07)
**Systemic complexity** — compounding unrecognised design errors, as opposed to repayable debt (ch04)
**Technical debt** — a conscious, local simplification that can be repaid (ch04)
**Tool manifest** — the list of tools, arguments and descriptions given to the model (ch02, ch06, ch07)
**Trace** — recorded tree of an agent run: model calls, tool calls, results, retries and cost (ch08)
**Vendoring** — copying a small library into the project (ch04)
**Adversarial review** — asking a second model or tool to attack a plan or diff with a specific objective (ch09)
**Blind-spot pass** — read-only parallel exploration of a codebase before changes, sorting unknowns into known knowns, known unknowns, unknown knowns and unknown unknowns (ch09)
**Builder vs judge** — the principle that the model that builds should not be the only one that reviews (ch09)
**Contract first** — fixing shared shapes (for example the API between backend and frontend) before parallel work starts (ch09)
**Deterministic core** — the part of an agent written as fixed code or scripts, with the model deciding only at named points (ch10)
**Directive** — a plain-text procedure the orchestrating model reads and the scripts carry out (ch10)
**Effort setting** — a control for how much reasoning a model does; lowering it shortens reasoning, not the reply (ch09)
**Fixed prefix** — tokens present before your first message: system prompt, instructions file, skill descriptions, tool definitions (ch09, ch07)
**Handoff file** — a written summary of goal, decisions, problems, files and next steps used to start a fresh session (ch09)
**Hook** — an action that runs deterministically before or after an agent action, unlike an instruction, which is advisory (ch09)
**Instructions file (index)** — short persistent file of rules that points to documents read on demand (ch09, ch02)
**Protocol server** — a service exposing selected tools or workflows to an assistant through a standard protocol; the description is the interface (ch10, ch07)
**Skeleton (generated workflow)** — the first generated flow, needing review of credentials, branches and field names (ch10)
**Sub-agent vs agent team** — sub-agents work in parallel without talking and cost less; teams message each other and share tasks and cost more (ch09)
**Working copy (worktree)** — a separate checkout of a repository so parallel sessions do not collide (ch09)
