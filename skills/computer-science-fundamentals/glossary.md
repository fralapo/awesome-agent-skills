# Glossary

**A*** - Dijkstra-style search ordered by cost so far plus an estimate of the cost remaining (ch2)
**Acknowledgement (cumulative)** - receiver's statement that everything up to a sequence number has arrived (ch7)
**AES** - 128-bit symmetric block cipher with 10, 12 or 14 rounds of substitution, row shift, column mix and key addition (ch8)
**AIMD** - additive increase, multiplicative decrease: grow the window by one per round, halve on loss (ch7)
**Atomic exchange** - hardware instruction that writes a value and returns the old one indivisibly; the basis of a mutex (ch5)
**Base case** - the input on which a recursion stops (ch2)
**Big-O** - notation for how cost grows with input size (ch1)
**Binary search** - halving search on sorted random-access data (ch2)
**Bloom filter** - bit array plus hash functions that answers "definitely not" or "maybe" (ch3)
**B-tree** - tree with many sorted keys per node, shallow, suited to disk (ch3)
**Busy beaver** - largest output of a halting machine of given size; uncomputable (ch1)
**Cache line** - fixed block (64 or 128 bytes) moved between memory and cache (ch4)
**Cache set / way / tag** - set chosen by address bits, ways are the candidate slots, tag is compared to find a hit (ch4)
**Certificate** - signed binding of a public key to an identity (ch9)
**Cipher block** - fixed-size unit (128 bits for AES) a block cipher transforms (ch8)
**Congestion window** - sender's estimate of how much data the network can carry in flight (ch7)
**Counter machine** - model with counters that can be incremented, decremented and tested for zero (ch1)
**Cuckoo hashing** - hash table where a key has several candidate slots and evicts occupants (ch3)
**DC balance** - equal number of ones and zeros on average on a line (ch7)
**Deadlock** - parties each wait for one held by another forever (ch5)
**Diagonalisation** - applying a thing to its own description to prove a limit (ch1)
**Diffie-Hellman ratchet** - re-seeding a key chain with fresh public values carried in messages (ch9)
**Dijkstra's algorithm** - shortest paths by always expanding the cheapest unfinished node (ch2)
**DNS** - distributed hierarchical name database mapping host names to addresses (ch7)
**Double ratchet** - key-derivation chain plus Diffie-Hellman ratchet for messaging (ch9)
**DRAM / SRAM** - capacitor-based memory that leaks and needs refresh / flip-flop memory that is fast and power-hungry (ch4)
**Entropy** - average information per symbol, the limit for lossless coding (ch3)
**Facade** - simplified interface in front of subsystems (ch10)
**Finite field (Galois field)** - set with addition, multiplication and inverses and no overflow; 256 elements = a byte (ch3, ch8)
**Garbage collection** - automatic reclaiming of unreachable memory (ch6)
**Halting problem** - deciding whether a program stops; no general algorithm (ch1)
**Hash (digest)** - fixed-size, non-reversible fingerprint of data (ch8)
**Heap / stack** - long-lived object memory / call-frame memory (ch6)
**Huffman code** - optimal prefix code built by merging the two least likely symbols (ch3)
**Idempotent** - safe to repeat with the same effect as once (ch5)
**Incompleteness** - consistent systems containing arithmetic have unprovable truths and cannot prove their own consistency (ch1)
**Inode** - file metadata plus data pointers; names live in directories (ch6)
**Interrupt** - hardware signal that makes the CPU run a handler (ch6)
**Livelock** - parties keep reacting to each other without progress (ch5)
**Man in the middle** - party in the path who can read or alter traffic (ch9)
**Mark and sweep** - collector that marks reachable objects and frees the rest (ch6)
**Modular arithmetic** - arithmetic on a clock of fixed size (ch8)
**Monte Carlo tree search** - sampling-based tree search with selection, expansion, simulation, backup (ch2)
**Mutex** - lock giving one holder at a time (ch5)
**Nonce** - fresh random value used once in a protocol (ch9)
**NP / NP-complete** - checkable in polynomial time / hardest of NP (ch1)
**Page / page table / TLB** - memory chunk (4 KB), translation tree, cache of translations (ch4)
**Prefetch** - fetching data before it is asked for (ch4)
**Proof of work** - problem hard to solve, easy to verify, used to agree on a ledger (ch9)
**Race condition** - result depends on timing of interleaved steps (ch5)
**Reed-Solomon code** - symbol-based error-correcting code using finite fields (ch3)
**Reference counting** - freeing when a holder count reaches zero; fails on cycles (ch6)
**RSA** - public-key scheme based on factoring a product of two primes (ch8)
**Slow start** - exponential window growth at connection start (ch7)
**Square and multiply** - exponentiation by repeated squaring guided by exponent bits (ch8)
**Syndrome** - remainder pattern that signals and locates damage in an error-correcting code (ch3)
**System call** - controlled entry from user code into the kernel (ch6)
**System on a chip** - several components on one package (ch4)
**Token (web)** - signed credential held by the client (ch9)
**Turing machine** - tape, head and rules; reference model of computation (ch1)
**Virtual memory** - per-process address space translated to physical memory (ch4)
