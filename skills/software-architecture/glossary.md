# Glossary

**Accept queue** - kernel queue of fully established connections waiting for the application to accept them (ch13)
**Access pattern** - how data is actually requested; the input to key, shard and cache choices (ch01, ch05)
**Agent** - a model in a loop with tools and memory, wrapped by code you control (ch11)
**Agentic retrieval** - an agent chooses which data source or tool to query in a loop (ch10)
**ALPN** - negotiation of the application protocol inside the TLS handshake (ch13)
**API gateway** - edge service that authenticates, routes and limits calls to many backends (ch16)
**Association (edge)** - a typed, timestamped link between two objects in a graph store (ch08)
**Asynchronous replication** - primary does not wait for the copy; lag possible (ch02)
**Availability zone** - an isolated failure domain inside a region (ch06, ch08)
**Avalanche (cache)** - many keys expiring together or a cold cache sending all load to the database (ch06)
**Backlog / SYN queue** - bounded kernel queues for half-open and completed connections (ch13)
**Base 62** - number encoding with digits and both letter cases, used for short codes (ch09)
**Bin packing** - fitting tasks into machines; best fit vs fast fit vs hybrid (ch08)
**Blast radius** - how many places feel a change to a dependency (ch18)
**Bloat** - dead row versions and index entries that take space until vacuum reclaims them (ch14)
**Bloom filter** - structure that says "definitely absent" or "maybe present"; no false negatives (ch04)
**Bounded queue** - request queue with a maximum length, rejecting beyond it (ch03)
**Cascading failure** - one failure shifts load and causes the next (ch03)
**CDN** - network of edge copies of content close to users (ch06)
**Change log** - ordered record of writes used for replication, backups, indexes and recovery (ch04)
**Checkpoint** - flushing modified pages to disk so the log before it is no longer needed for recovery (ch14)
**Choreography** - services react to events with no central coordinator (ch20)
**Chunk** - the unit of text embedded and retrieved in RAG (ch10)
**Circuit breaker** - stops calls to a failing dependency for a while so it can recover (ch03, ch06)
**Compaction** - merging sorted files to reclaim space and speed reads (ch04)
**Competing consumers** - several instances share one queue to raise throughput; moves the bottleneck (ch07, ch19)
**Consensus** - agreement of nodes on one value or leader (ch02)
**Consistent hashing** - placing keys and nodes on a ring so changes move few keys (ch05)
**Constant work** - doing the same backend load regardless of cache state, for predictability (ch03)
**Copy-on-write** - sharing memory until one side writes, then copying the page (ch12)
**Cross-encoder** - model scoring a query-text pair token to token, used to re-rank (ch10)
**Dangling edge** - one half of a pair of dependent writes, later repaired (ch02)
**Delayed message** - message the broker holds until its due time, used to schedule follow-ups (ch20)
**Denormalisation** - duplicating data to avoid joins (ch04)
**Dual write** - writing state and publishing a message as two separate operations (ch19)
**Effectively once** - correct outcome despite duplicates and retries, rather than literal exactly once (ch20)
**Embedding** - vector representing meaning of text, so near means similar (ch10)
**Entity service** - one service owning all data of an entity for everyone; couples consumers (ch18)
**Ephemeral port** - short-lived local port assigned to an outgoing connection; a finite pool (ch13)
**Event sourcing** - persisting the facts from which state is derived (ch19)
**Event-carried state transfer** - events that copy entity data to other services (ch19)
**Eventual consistency** - copies converge if writes stop; reads may be stale (ch02)
**Fan-out** - number of recipients one message or write reaches (ch05, ch07)
**Gateway** - connection-holding edge service doing little else (ch07)
**Geohash** - hierarchical cell code where longer strings are sub-cells (ch05)
**Global secondary index** - index with a different partition key, a copy updated from the stream (ch04)
**Gossip** - peer-to-peer spread of membership or ownership information (ch05)
**Graph retrieval** - following links from a retrieved document to related ones (ch10)
**Guardrail** - rule limiting agent behaviour; prompt-level is advice, code-level is enforcement (ch11)
**Harness** - the code around the model: prompts, tools, memory, limits (ch11)
**Head-of-line blocking** - one slow request blocking those behind it (ch06)
**Health check** - probe deciding whether a server receives traffic; a wrong one can withdraw healthy servers (ch03, ch15, ch16)
**Heartbeat** - periodic signal showing a node or client is alive (ch07, ch16)
**Hot shard** - a partition receiving disproportionate load (ch05)
**Huge page** - large memory page that shrinks page-table and TLB overhead (ch12)
**Hybrid fit** - placement that packs snugly but leaves headroom (ch08)
**Idempotent** - safe to repeat with the same effect as once (ch02)
**Inbox (deduplication) table** - unique message ids recorded in the same transaction as the state change (ch14, ch20)
**Integration event** - event published as a contract to other boundaries (ch19)
**Iteration cap** - maximum steps in an agent loop (ch11)
**Jitter** - random spread of timing to avoid synchronised bursts (ch03)
**Kernel mode** - privileged execution for system calls; switching in and out has a real cost (ch12)
**Layer 4 / layer 7 proxy** - balances by connection or by parsed request content (ch16)
**Leader election** - choosing the node that accepts writes (ch02)
**Linearized eventual consistency** - one ordered timeline where readers differ only in position (ch19)
**Load shedding** - rejecting excess work to protect the rest (ch03)
**Local secondary index** - alternative sort within the same partition (ch04)
**Log-structured merge** - buffer, flush sorted immutable files, merge in background (ch04)
**Logical boundary** - ownership of behavior, rules, lifecycle and meaning; separate from deployment (ch18)
**Look-aside cache** - the caller reads the cache, falls back to the database and fills the cache (ch06)
**Multiplexing** - many logical requests interleaved on one connection (ch13)
**MVCC** - keeping several versions of a record so readers pick an isolation level (ch02)
**Nines** - availability expressed as 99.9%, 99.99% and so on (ch03)
**Noisy neighbour** - a tenant whose load degrades others on shared resources (ch18)
**OAuth 2** - delegated authorization through tokens issued by an authorization server (ch16)
**Orchestration** - a coordinator holds the process state and sends commands (ch20)
**Outbox** - table written in the same transaction as the state change and relayed to the broker (ch19)
**Overflow pool (gutter)** - spare cache nodes used only on failure (ch03, ch06)
**Page fault** - access to memory not mapped yet or not permitted; the kernel resolves it (ch12)
**Page table** - multi-level map from virtual to physical memory addresses (ch12)
**Partition key / sort key** - hash key choosing the partition / ordering key inside it (ch04)
**Policy (process gatekeeper)** - records which preconditions arrived and acts when all have, in any order (ch19)
**Preemption** - evicting lower-priority work for higher (ch03)
**Projection (read model)** - state derived from events or data, shaped for queries (ch19)
**Quorum** - majority of replicas agreeing on a read or write (ch02)
**RAG** - retrieve context, augment the prompt, generate (ch10)
**Rate limiting** - capping accepted requests (ch03, ch04)
**Re-ranking** - rescoring top candidates with a more precise model (ch10)
**Read-your-writes** - a writer sees their own write immediately (ch02)
**Reconciliation** - comparing your state with the system that owns the truth and applying a safe fix (ch20)
**Replication factor** - number of copies of each item (ch02, ch05)
**Request coalescing** - merging identical concurrent requests into one backend query (ch16)
**Request smuggling** - exploiting two parsers that disagree on where a message ends (ch13)
**Reservation** - time-bound lock with reserve, confirm and expire behaviors (ch20)
**Retry budget** - cap on retries so recovery traffic cannot swamp a dependency (ch03)
**Saga** - long transaction split into steps with compensation (ch02)
**Selectivity** - fraction of rows a predicate matches; low selectivity makes an index useless (ch14)
**Service discovery** - finding the current addresses of a service's instances (ch16)
**Session service** - maps users to the gateway holding their connection (ch07)
**Sharding** - splitting data into key ranges across nodes (ch05)
**Single point of failure** - one component whose failure stops the system (ch02)
**Slow start** - exponential growth of the congestion window at connection start (ch13)
**Sorted string table** - immutable sorted file of key-value records (ch04)
**Spin lock** - lock that busy-waits; a preempted holder stretches the critical section (ch12)
**Split brain** - two nodes both acting as primary (ch02)
**Stampede (cache)** - many requests recomputing the same expired hot key (ch06)
**Status-only record** - a record that stores only "status" changes and loses the reason for each change (ch17)
**Strong read** - read served by the leader with the latest value (ch02)
**Thundering herd** - synchronised surge of requests (ch03)
**TLB** - translation cache for recent virtual-to-physical lookups (ch12)
**Token bucket** - credit accumulating at a rate, spent by bursts (ch04)
**Tombstone** - marker hiding deleted records until compaction (ch04)
**Tool (function call)** - callable capability exposed to a model (ch11)
**Tool protocol (MCP-style)** - run-time discovery of tools from a provider's server (ch11)
**Transaction script** - procedural handling of a use case in one transaction without a rich model (ch17)
**Tuple id** - physical location of a row version; indexes point to it (ch14)
**Two-phase commit** - coordinated commit across nodes; slow (ch02)
**Vacuum** - process reclaiming dead row versions (ch14)
**Vector database** - store with nearest-neighbour search over embeddings (ch10)
**Watch service** - pushes selected changes to listeners off the hot path (ch04, ch08)
**WebSocket** - persistent bidirectional connection (ch07)
**Write amplification** - physical writes caused by one logical write (ch04)
**Write-ahead log** - journal forced to disk before data pages, used for commit and recovery (ch14)
