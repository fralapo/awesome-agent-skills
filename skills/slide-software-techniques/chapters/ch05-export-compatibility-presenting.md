# Chapter 05: Export, Compatibility & Presenting

## Core Idea
Every software — and every version of the same software (Keynote desktop vs iCloud web, old vs new PowerPoint) — reinterprets animations, transitions, transparencies, fonts and arrows differently, so every export is a compromise: you either drop animations or rebuild them. Two rules prevent disasters: know in advance on which software and machine the deck will be shown, and rehearse the actual file on that setup before going on stage. Design in the destination software whenever possible (if the client needs a .pptx, design in PowerPoint; if you use Canva, deliver a Canva link), carry a PDF safety copy, and present only in full-screen presentation mode with presenter view, a remote, and speaker notes instead of text-heavy slides. Online, share only the slide window and keep notes on your side; treat lighting, microphone and camera as part of the deck.

## Frameworks Introduced
**Two compatibility rules**: (1) ask which software, version and computer will be used on the day; (2) test the file on that setup before presenting. If you can plug in your own device, the problem disappears.
When to use: at briefing (the "technical context" question: technologies, cables, software, fonts to embed) and again in the last rehearsal.

**Native-format delivery**: deliver in the format of the destination tool — .pptx/.potx for corporate PowerPoint, Keynote file for Mac presenters, live link for Canva/Google Slides — plus a PDF backup.
When to use: every handover.

**Export format trade-off table (Keynote > File > Export To)**:
- PDF: opens everywhere; options for presenter notes, printing each build stage, image quality, password, skipped slides, comments. Loses animations; present it full screen, never scrolling.
- HTML: index.html + assets folder; runs in any browser with animations (some errors); carry the whole folder or upload it and share a URL; no presenter notes; not available from iPad or Keynote web.
- PowerPoint: keeps presenter notes but misreads animations (Magic Move does not become Morph, fades get converted), loses transparencies, breaks fonts and arrows → plan to redo much of the work; check the destination PowerPoint version. Also available from iPad.
- iCloud/Keynote web: drag the file into the iCloud Keynote folder; non-system fonts missing, some arrows break, Magic Move stutters; storage limits.
- Movie (fixed seconds per slide, no live control), animated GIF (quality loss from limited colors), Images (each slide or each build), Keynote '09 for old versions.
When to use: choosing a fallback when you cannot present from your own machine.

**Presenter stack**: full-screen presentation mode + presenter view (current slide, next slide, notes, timer) + remote (clicker, smartphone, or iPad) + notes that hold what the slides do not say.
When to use: every live talk, pitch, defence, training.

**Online two-window setup**: audience window shared through "Share window", presenter window with notes kept private (Keynote Play in Window, Canva presenter view, Figma/Google Slides two windows).
When to use: webinars, video calls, remote trainings.

**Slide vs document**: a deck to be presented supports the voice (keywords, schemas, images); a deck to be sent is read alone and may hold more text and clickable navigation. Decide which one you are exporting.
When to use: when the same content must be both projected and emailed; when a teacher or client asks to "write everything" (that is a document).

## Rules & Numbers
Format decision at a glance:

| Situation | Deliver | Backup |
|---|---|---|
| Corporate PC, PowerPoint | .pptx (and .potx if a template) designed in PowerPoint | PDF |
| Own Mac can be plugged in | Keynote file | PDF |
| Unknown non-Apple PC, Keynote design | PowerPoint export repaired and tested, or HTML folder | PDF |
| Canva or Google Slides | view-only link (saved offline) | PDF |
| Deck sent by email | PDF, optionally interactive (internal/external links) | — |

- Cross-software: Keynote → PowerPoint and Canva → PowerPoint both shift text, change transitions and substitute fonts.
- If a .pptx is required, design in PowerPoint from the start; designing in Keynote then exporting means fixing incompatibilities by hand. Keynote files must be exported and tested in PowerPoint because the two are not fully compatible.
- Check the destination PowerPoint version: old and new versions interpret objects differently.
- Canva: don't export to PowerPoint — the advantage of Canva is that it is online and one link shares it.
- Google Slides cannot hold most Keynote/PowerPoint motion: converting a Keynote deck to Google Slides means rebuilding nearly everything and sacrificing animations.
- Present with the same software used to design; otherwise animations are converted or removed.
- Fonts: decide at briefing whether fonts must be embedded or whether only system/Google fonts are safe on the presenting machine; web versions (Keynote iCloud) lack non-system fonts.
- Always keep a PDF safety copy (it loses animations and, by default, presenter notes).
- Check the exported PDF: builds where later elements cover overlapping images do not translate, and the stacked images all show at once. Use "print each stage of builds" when the sequence matters.
- A PDF also suits documents sent by email; dense text is acceptable only there.
- Interactive PDF: internal links for non-linear navigation (clickable index, home icon, prev/next arrows), external links for heavy or dynamic material (other case studies, videos); add a legend slide; test every link twice and have someone else test them.
- Format: always 16:9; converting an old 4:3 deck is the occasion to update content and graphics.
- Printing/handouts: dark backgrounds are heavy in print; several slides per sheet when splitting dense content across more slides.
- Schools and online platforms: share a link/account; otherwise PDF (opens everywhere, loses animations).
- Online platforms (Canva, Google Slides): share a link/account; save the link offline so login problems don't block you.
- 3D models and heavy animated decks lag on low-performance PCs: test on the presenting computer.
- Online presentations: animations may lag and fades stutter; prefer simple one-click appearances (an "all at once"/Appear reveal without movement), and avoid many-step builds.
- In calls share the audience window, not the whole screen, so notes, other apps and notifications stay private.
- Keynote HTML export can be uploaded to a server/domain and shared as a link that runs with animations in any browser.
- Movie export removes live control (fixed seconds per slide): only for unattended loops or recorded content.
- Presenting: always full-screen slideshow, never from edit/design mode.
- Remote: always use a presenter/clicker when live (from about €10); a smartphone works too. Staying behind the laptop to press keys makes the performance rigid; the best speakers stand, move and use space.
- iPad as remote (Keynote Remote): draw and circle on slides live, see previous/next slide and presenter notes.
- Speaker notes: the place for everything you fear forgetting; the view is visible only to the presenter. Slides must not say everything ("if you write everything, what does your voice add?"). Alternatives: neat cue cards or a sheet.
- Move a client's excess slide text into the speaker notes rather than shrinking it.
- Animation timing on the day: one animation type for the whole deck (fade), On Click only for the items cited at that moment; waiting for elements to appear creates embarrassing silences.
- Annotating live (circling, writing on slides) is possible from an iPad with a pencil running Keynote; useful in trainings.
- Rehearsal in three stages: alone with the slides (natural transitions), in front of people (emotional state and logic), in the venue (space, microphones, monitor).
- Check constraints from the organiser/teacher/university: format, maximum number of slides, imposed colors or template, which PC projects.
- Slide count does not set duration: a visual slide may last 10 s, a schema much longer; a 20-minute talk can carry 33 slides. Rough rule seen: ~15 slides per 10 minutes, but content decides.
- Webinar lighting: an LED panel lighting the face from one side, an accent light (e.g. a tube in the brand color) on the other, a few background lights for atmosphere.
- Webinar audio/video: a dedicated microphone around €100 is enough (no need for a €500 one); a mirrorless camera connected to the computer, or the laptop webcam if lighting is good.
- Webinar control: slides driven from a second device (iPad) for dynamic control.
- Presenting in the dark with poor audio damages the impression regardless of the slides: the setting is part of the experience.
- Waiting slide before an event/webinar: slow looped background motion (see Chapter 03).
- Before delivery: Slide Sorter review for consistency, hidden (not deleted) spare slides, durations of animations checked.

## Procedures
**A. Pre-delivery checklist**
1. Ask: which software and version, which computer (yours or the venue's), local file or online, projector/monitor ratio (16:9), cables/adapters.
2. Ask whether fonts must be embedded or substituted; if unsure, use system or Google fonts.
3. Design in the destination software; if converting, budget time to rebuild Morph/Magic Move and transparencies.
4. Export a PDF safety copy (check build stages and covered images).
5. For online tools: set sharing (Canva: Share > Anyone with the link > Can view) and store the link offline.
6. Test the final file on the presenting machine, including 3D/video playback and animation timing.

**B. Keynote export for non-Apple machines**: File > Export To > PDF (tick presenter notes / each stage of builds as needed, image quality, password) or HTML (carry the whole folder; or upload and send the URL) or PowerPoint (then open in the target PowerPoint version and repair animations, transparencies, fonts and arrows). For iCloud: drag the file into the Keynote iCloud folder from Finder and rehearse there.

**C. Online presenting**
1. Keynote: Play > Play in Window; in Meet/Zoom share that window only; presenter view stays on your screen.
2. Canva: Present > Presenter view; share the audience window with Share window.
3. Google Slides / Figma Slides: presenter view opens a notes window and a slides window; share the slides window.
4. Reduce builds to one-click appearances if the connection is weak.
5. Lights: key light on the face, accent/brand light, background lights; dedicated mic; mirrorless or webcam; slides controlled from iPad or remote.

**D. iPad as remote**: open the remote app on the iPad and the presentation on the computer, tap the device/phone icon at the top right, then the green play button; the show starts and the iPad shows previous/next slides, notes, and lets you annotate.

**E. Day-of routine**: full screen; remote in hand; notes in presenter view; PDF and link backups on a USB stick/cloud; one test click through the first slides on site; spare slides hidden at the end, not deleted.

## Common Mistakes
- Discovering on site that the venue PC runs a different software → ask at briefing; bring your device or a native-format file.
- Exporting Canva to .pptx for a corporate client → design in PowerPoint or deliver the Canva link.
- Exporting Keynote to PowerPoint and presenting without checking → Magic Move lost, transparencies opaque, fonts swapped; repair and rehearse.
- Presenting from iCloud web without testing → missing fonts, broken arrows, stuttering Magic Move, opaque transparencies.
- Scrolling a PDF in a viewer → full-screen presentation mode.
- Presenting from the design view or behind the keyboard → slideshow mode and a clicker.
- Sharing the whole screen in a call → share only the audience window, keep notes private.
- Writing the whole speech on slides "in case I forget" → speaker notes or cue cards.
- Heavy 3D/loop decks on a weak laptop → test performance; fall back to fades.

## Mental Models
- Any export is a compromise: decide in advance which compromise you accept.
- The deck is not finished when it looks good on your machine; it is finished when it runs on the presenting one.
- The setting (light, sound, remote, window sharing) is part of the presentation experience.
- The audience is on your side and wants you to succeed; good preparation removes the technical reasons to fail.
- Slides support the voice: whatever the audience needs only for later reading belongs in a PDF document or in the notes.

## Examples
- A deck shown from cloud storage on the venue machine: animations stopped working and transparent objects turned opaque; the fix was asking for the presenting software in advance and delivering a native file tested on it.
- A thesis defence: Keynote/PowerPoint file plus a PDF safety copy, one animation type (fade) On Click only for cited items, rehearsals alone, with people and in the room, remote or smartphone, speaker notes.
- An online training run with Keynote Play in Window: only the slide window shared on the call, presenter view with notes and next slide kept private, slides advanced from an iPad.
- A school presentation made in Canva shared as a view-only link saved on a USB stick, avoiding dependence on account login on exam day.
- A webinar host setup: side LED panel, brand-colored accent tube, ~€100 microphone, camera on the computer, deck driven from an iPad.
