# Chapter 6: Network Architectures: Dense, Convolutional, Autoencoders and Generators

## Core Idea
An architecture is a set of structural assumptions that makes learning feasible for a kind of data. In this model, choose the architecture by asking what symmetry or structure the data has, then check whether the assumption costs you something elsewhere.

## 6.1 Dense (fully connected) networks
- **Thesis**: the simplest network connects every unit of a layer to every unit of the next; it is a universal building block and the base of the feed-forward part of larger models.
- **Mechanism**: matrix multiplication, bias, nonlinearity, repeated. Parameter count is the product of layer sizes: 784 inputs by 16 hidden units is already 12,544 weights.
- **Trade-off**: no built-in structure, so it needs much data and ignores that nearby pixels or words are related.
- **Does not hold when**: inputs are large images or long sequences; parameters and cost explode.

## 6.2 Convolutional networks
- **Thesis**: reuse one small detector at every position of the input.
- **Mechanism**: a kernel (a few weights) slides across the image; each output is the weighted sum of a local patch (the convolution operation of chapter 2). Early filters detect edges, later ones combine them into parts and objects. Weight sharing slashes parameters and gives translation-equivariance.
- **Trade-off**: strong bias that suits images, audio and local structure; long-range relations need many layers or other mechanisms.
- **Does not hold when**: the signal has no locality (set-like data) or the absolute position matters.

## 6.3 Autoencoders: compress to learn what matters
- **Thesis**: train a network to reproduce its input through a narrow bottleneck; the bottleneck code is a learned compact representation.
- **Mechanism**: same number of input and output units, a much smaller middle layer, loss on reconstruction error. Variants: denoising (reconstruct the clean input from a corrupted one), sparse, and variational (the code is a distribution that can be sampled to generate new examples).
- **Trade-off**: autoencoders were not better than classical codecs for plain compression; their value is the representation and generation.
- **Does not hold when**: the bottleneck is too wide (identity copy, nothing learned) or too narrow (blurry reconstructions).

## 6.4 Sparse autoencoders as an analysis tool
- **Thesis**: the same idea is used on a model's internal activations to look for the features it uses.
- **Mechanism**: reconstruct activations through a wide, sparse code; hope each code unit corresponds to one interpretable feature even when features are superimposed across raw neurons (chapter 11).
- **Trade-off**: gives readable units at some reconstruction error; the features it finds are partly a product of the method.
- **Does not hold when**: you treat found features as complete or causal without intervention tests.

## 6.5 Generative models in outline
- **Thesis**: a generative model learns a distribution over data so that new samples can be drawn; images, audio, video and text are generated by learned processes rather than copied.
- **Mechanism**: families include variational autoencoders, adversarial pairs, autoregressive models (text, next-token) and iterative denoising. A common recipe is to learn to remove noise step by step and run the process from pure noise.
- **Trade-off**: realism improves with scale and data; faithfulness to physics or facts does not follow automatically.
- **Does not hold when**: you need consistency of world state over long outputs (objects reappearing, physics): current generators still fail there, and more data does not guarantee an accurate world model.

## 6.6 Learned simulators
- **Thesis**: a network can be trained once on simulations to predict the next state, then run in milliseconds where the simulator needed minutes.
- **Mechanism**: show many fluid or smoke simulations; the network learns the dynamics well enough to roll forward. Training is an expensive pre-processing step; inference is cheap, like long exam preparation followed by fast answers.
- **Trade-off**: speed against guarantees: failure modes of hand-written physics can be read from the equations, those of a network are harder to predict; early results may not be peer-reviewed.
- **Does not hold when**: you need certified accuracy or the situation is far from the training simulations.

## 6.7 Choosing an architecture
- **Thesis**: match structure to data and constraints, then test.
- **Mechanism**: tables go to trees or boosting first; images to convolutions or attention; sequences and language to transformers (chapter 7); signals with periodic structure may benefit from frequency features; small data favours strong priors; deployment limits favour pruned or distilled models.
- **Trade-off**: simpler models are cheaper and easier to audit.
- **Does not hold when**: a general architecture plus enough data and compute beats handcrafted structure (chapter 12).
