# Chapter 32: Redesigning Transactional Flows and Gestures

## Core Idea
Simplify a transaction by removing jargon, ordering actions by frequency, making clickable elements obvious and showing the effect of every choice. Design gestures so one gesture means one thing and works on the first attempt. Worked methods that apply ch17-ch19 to a kiosk-style or touch flow. (Some source passages were low quality captions; only clear rules are kept.)

## Transactional Flow Method
1. **Know the actual user** (for a public ticket machine, mostly visitors unfamiliar with the place).
2. **Wireframe structure and hierarchy first**, then apply visual design.
3. **Hierarchy by frequency**: the most common action is largest; secondary and tertiary actions smaller; rare options under "other". Aim for about six primary buttons on the main screen.
4. **Translate codes into outcomes**: a zone code becomes "90 minutes", "24 hours", "3 days", "10-ticket pack". Unexplained codes get misread (as line names).
5. **Remove information implied by context**; do not repeat it.
6. **Make clickables look clickable**: contrast, shape, highlight. Do not mix ads and buttons on one screen.
7. **Navigation placement**: "back" on the left, "forward/confirm" on the right.
8. **Show effects**: a live total; at a maximum, disable the increment and state the limit.
9. **Price on the first screen**, not behind navigation.
10. **Language and help**: most-used language first, selected state visible, both reachable from every screen.
11. **Output artifact** (ticket): clear size hierarchy, place name, key rules, one visual cue, an emotional touch only if it supports recall.

## Gesture Design Rules
- Do not map one swipe to several destinations (the same downward swipe for notifications and for controls).
- Merge hold, slide and release into one continuous motion rather than hold, release, then tap.
- Customisation follows direct manipulation: drag to rearrange where items appear, not a disconnected settings list.
- Media controls show complete information, have large targets and survive interruption by another audio source.
- A preview or peek earns its place only if faster than open-and-close.
- Hover-only behaviours need a touch equivalent (ch29).

## Mistakes
- Equal-weight buttons and repeated information.
- Tiny tap targets.
- Visual polish before structure is fixed.
- Settings lists detached from the spatial layout.

## Checklist
- [ ] Frequency order drives size and position.
- [ ] No unexplained codes; outcomes stated.
- [ ] Total and limits visible live.
- [ ] Back left, confirm right; selected states shown.
- [ ] One gesture, one meaning, first-try success.
